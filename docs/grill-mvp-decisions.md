## 一、业务 MVP 主干（已锁定）

单对象线性流水线，13 阶段，无门禁机制：

```
机会判断 → 投入验证 → GTM投流验证 → 供应链小批量履约 → VOC售后验证 → 财务利润测算
→ 投决(通过/否决)
→ 产品优化 → 产品上市 → GTM投流 → 供应链履约 → VOC售后 → 利润核算
   └─ 经营层：新品期 → 老品期 → 成熟期维护 → 退市(终态)
```

### 实体与状态

| 维度     | 决策                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 实体模型 | 单对象（机会/产品一体），线性状态机，三段分组展示（开发验证期 / 上市执行期 / 经营层） |
| 投决     | 二分（通过 / 否决），通过继续、否决 = 终态；不做门禁评审机制                          |
| 阶段推进 | 随便推进、可回退可改；改完全链利润自动重算；无「数据齐才能进」约束                    |
| 经营层   | 利润核算后进入，`经营状态` 字段手工切换；退市 = 终态                                  |

## 二、数据与利润（已锁定）

结构化表单只给「算钱/验证」阶段，其余阶段仅推进状态：

| 阶段                          | 结构化字段                                                     |
| ----------------------------- | -------------------------------------------------------------- |
| 投入验证                      | 投入成本                                                       |
| GTM投流验证 / GTM投流         | 广告成本、销售额（毛额）                                       |
| 供应链小批量履约 / 供应链履约 | 产品成本、履约成本                                             |
| VOC售后验证 / VOC售后         | 退款额、售后成本                                               |
| 财务利润测算                  | 预计收入 / 预计成本 / 预计利润（手工预估，不算数、不参与核算） |
| 利润核算                      | 自动聚合                                                       |

**利润公式**（全生命周期，验证期 + 执行期都算）：

```
利润 = Σ销售额 − Σ广告成本 − Σ产品成本 − Σ履约成本 − 投入成本 − Σ退款额 − Σ售后成本
```

- 销售额 = 毛额（含后来退货的订单），退款额单独扣除
- 聚合逻辑放 `common` 纯函数，前后端共享

### 界面与权限

| 维度   | 决策                                                                           |
| ------ | ------------------------------------------------------------------------------ |
| 主界面 | 管道看板：每行一条机会，显示当前阶段 / 投决结果 / 实时聚合利润；点进详情录数据 |
| 权限   | 全员平权：业务用户 + 只读 两个角色；投决无单独权限点                           |

## 三、工程范围（已锁定）

| 维度         | 决策                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 仓库         | 单仓库 monorepo + GitHub Actions CI/CD                                                                                         |
| 前端         | 3 个全建（owl-web / admin-web / cron-web），**一个登录态（SSO）**，不同路由前缀（owl/ /admin/ /cron/）指向不同前端             |
| cron-service | MVP 只做一个「飞书多维表格 → 系统」定时同步任务，**纯管道测试**（验证 cron + RabbitMQ + 同步逻辑），验证完可弃，与业务数据无关 |
| 底座         | 10 个模块全做：auth / user / role / permission / audit-log / notification / file / system-config / mcp + 新增业务 project 模块 |
| MCP          | 只读工具口径（对 MD 附录 K）                                                                                                   |

## 四、与 MD 的偏差（Phase 2 再补）

本次 MVP 对 MD 显式裁剪，以下**均不在本次范围**：

- 两层模板模型（template_version / node_def / 节点配置）
- G1-G5 门禁 / 评审人 / reviewer_record / 多评审人 / 治理层一票否决
- 红线自动判（验证协议附录 E 本次不生效）
- 失败知识库
- 基础数据域（SPU / 供应商 / 渠道 / 市场）；机会对象市场 = 自由文本
- 投决权限点
- 多渠道素材投放、VOC 工单闭环、止损红线
- 供应链/运营/治理层业务域
- 多评审人 + 数据范围（scope）过滤
