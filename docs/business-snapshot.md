## 一、业务领域地图

| 领域                  | 定位                                                                                            | 主要入口               | 开发顺序          |
| --------------------- | ----------------------------------------------------------------------------------------------- | ---------------------- | ----------------- |
| 主业务链              | 产品研发（设计）→ 工厂代工（供应链）→ 品牌营销 → 四渠道（抖音 / TikTok Shop / Amazon / 独立站） | owl-web + admin-web    | 第四期（P4）      |
| 组织支撑域 · 人才中心 | 面试 → 入职 → 晋升/调岗 → 离职全生命周期；档案、奖惩、认可、激励记录                            | admin-web + mobile-web | 第二期（P2）      |
| 组织支撑域 · 认可中心 | **工作福利类**：跨部门协作认可、零碎紧急事务奖励、员工基础福利（独立闭环，不参与绩效）          | admin-web + mobile-web | 已完成，转维护    |
| 财务域 · 财务中心     | 记账、报销与费用、资金出纳；承接人才中心的考勤/薪酬/福利并出纳结算留档                          | admin-web              | 第三期（P3 一期） |
| 副业域 · 付费知识     | md 文档库                                                                                       | mobile-web + admin-web | 冻结，停止扩展    |
| 系统基座              | 权限、组织同步、审批记录、编号、导出、字典、审计                                                | 全端                   | 第一期（P1）      |

全局口径：组织架构以飞书为唯一事实源（公共 API + 每日定时同步）；审批发起与审批都在飞书，系统只做记录；RBAC 按钮级四层（菜单 / 路由 / 按钮 / 接口）；数据范围暂不做；登录生产走真实飞书 OAuth，本地 mock 可切角色。

## 三、最新计划与排期

- 顺序：P1 系统基座 → P2 人才中心 → P3 财务中心一期 → P4 业务链路跑通。
- P1 第一项：权限码表统一 + 角色授权（当前开工点）。
- 关键依赖：P2 算薪 → P3 工资入账；P3 记账 → P3 报销凭证；P2 档案 → P2 考勤/薪酬。
- 二期：税务、成本与利润、固定资产、合同台账、预算、真实渠道接入、采购与库存、内容工厂。
- 排期与验收细节见 `docs/implementation-plan.md`（唯一排期事实源）；权限决策见 `docs/decisions/012-permission-registry.md`；P1–P4 顺序与范围决策见 `docs/decisions/013-p1-p4-scope-and-order.md`。
- 旧文档口径：`docs/archive/grill-mvp-decisions.md` 已标记废弃；已移除的 `docs/business/*` 不再作为业务或排期依据。

## 四、待决事项与假设（各期开工前确认）

1. 飞书应用需开通通讯录与审批读取权限（P1-2 / P1-4 前）。
2. 科目表裁剪版需业务确认（P3-1 前）。
3. 飞书报销审批表单需按字段清单配置（P3-3 前）。
4. 薪资结构口径、社保公积金比例、个税专项附加扣除收集方式（P2-5 前）。
5. 一份 TikTok Shop 真实订单样例用于模拟字段对齐（P4-5 前）。
6. 数据范围（本人/本部门/下级/全部）暂不做，后续如需要新开 ADR。
