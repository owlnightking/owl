# Owl 实施计划（P1–P4）

> 决策依据：`docs/decisions/002`、`011`、`012`（权限码表单源）、`013`（P1–P4 顺序与范围定稿）。
> **本文档是排期与范围的唯一事实源**；业务功能现状见 `docs/business-snapshot.md`；ADR 只记录历史决策，冲突时以编号更大的 ADR 为准。
> 交付形态：单仓库 monorepo + GitHub Actions CI/CD，7 个应用（api-service / cron-service / admin-web / owl-web / mobile-web / cron-web / portal），K8s 命名空间 `owl`。
> 投入：开发 1-2 人。粗估为单人全职人日，不含需求反复，不作为交付承诺。

---

## 一、已锁定的前提

| 项       | 结论                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 组织架构 | 飞书为唯一事实源，公共 API + 每日定时同步；系统不做部门/人员增删改             |
| 审批     | 发起与审批都在飞书；系统只做记录（API + 定时拉取），不驱动业务单据状态         |
| 数据范围 | 暂不做；「我的」类接口仍按当前用户过滤                                         |
| 认可中心 | 工作福利类（跨部门协作、零碎紧急事务、基础福利），独立闭环，不参与绩效         |
| 绩效     | 三档 B+ / B（默认）/ C，季度；未录入自动 B                                     |
| 财务     | 小企业会计准则、本位币 CNY、替代代账、无历史账、9710+9810 出口、手动开票与申报 |
| 财务一期 | 只做 记账 / 报销与费用 / 资金出纳（+ 工资社保个税入账）                        |
| 业务一期 | 立项 → 设计 → 手办样 → 供应链 → 营销 → TikTok Shop（模拟数据）跑通             |
| SaaS     | 暂不做多租户与计费；高企认定不依赖 SaaS                                        |

## 二、总体路线

```
P1 基座 ──► P2 人才中心 ──► P3 财务一期 ──► P4 业务链路
   │            │                │                │
   └ 权限/组织   └ 档案/考勤/薪酬  └ 记账/报销/出纳  └ 立项→设计→打样→供应链→营销→渠道
                                    ▲
                         P2 推工资汇总 ─┘
```

| 期  | 目标                     | 交付后能干什么                                         | 粗估       |
| --- | ------------------------ | ------------------------------------------------------ | ---------- |
| P1  | 系统能用、权限正确       | 该看的人看得到、不该看的进不去；组织和审批数据自动进来 | 10–15 人日 |
| P2  | 人才全生命周期可管       | 从候选人到离职全流程留档；月度考勤确认；算薪出工资条   | 25–35 人日 |
| P3  | 账能记、钱能付、报销能走 | 报销走飞书审批 → 系统付款 → 自动记账 → 出报表          | 25–35 人日 |
| P4  | 业务链路可演示           | 一条产品线从立项走到 TikTok 模拟出单                   | 12–18 人日 |

## 四、P2 人才中心

| 批次                | 内容                                                                                               | 关键规则                                      | 验收                                       |
| ------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------ |
| **P2-1 员工档案**   | 飞书基础信息（只读）+ 本地扩展（身份证/学历/工作经历/紧急联系人/银行卡/社保公积金/合同/证书/附件） | 基础信息不可改；合同续签提醒                  | 档案完整可查、可导出                       |
| **P2-2 招聘面试**   | 招聘需求、候选人（去重/状态机/人才库）、面试轮次与评分表、Offer（关联飞书审批单号）                | 候选人手机号唯一                              | 一个候选人从初筛走到入职，记录完整         |
| **P2-3 异动记录**   | 转正/调岗/晋升/调薪/兼岗/汇报关系/离职                                                             | 每笔记录「原值→新值+生效日+审批单号」，不可改 | 档案按生效日呈现当前状态，历史可追溯       |
| **P2-4 考勤**       | 工作日历、假期类型与额度、请假/加班/出差记录、月度考勤表、上级系统内确认、锁定                     | 免打卡；锁定后才可推财务；未锁定不算薪        | HR 生成上月表 → 上级确认 → 锁定 → 推送成功 |
| **P2-5 薪酬**       | 薪资结构版本、月度算薪、工资条、社保公积金、个税累计预扣、银行代发文件                             | 绩效系数 B+1.2 / B1.0 / C0.8 可配             | 算薪结果与手工核对一致；工资条按人可见     |
| **P2-6 绩效与奖惩** | 季度三档评级（默认 B）、奖惩记录                                                                   | 未录入自动 B；改档走新记录                    | 季度结束自动补 B；奖惩可追溯               |
| **P2-7 员工自助**   | mobile：我的档案/工资条/考勤/请假记录/审批记录/认可                                                | 只看本人                                      | 本人数据正确，他人不可见                   |
| **P2-8 推财务接口** | 考勤月结、算薪汇总、社保公积金、个税、福利报销、奖惩金额                                           | 幂等，可重推                                  | P3 能收到并生成凭证                        |

## 五、P3 财务一期

| 批次                | 内容                                                                                                                  | 关键规则                                      | 验收                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| **P3-1 记账内核**   | 科目表（小企业准则裁剪）、辅助核算（部门/供应商/客户/员工）、手工凭证、模板、审核/记账/红冲、账簿、三大报表、期初建账 | 制单 ≠ 审核；已记账只能红冲；已结账期间不可改 | 手工录一套凭证，三大报表与科目余额表勾稽一致          |
| **P3-2 资金出纳**   | 账户、收付款单、银行流水导入、规则匹配对账、日记账、资金日报、票据、现金红线                                          | 未填飞书审批单号不能标记已付款                | 导入流水自动匹配付款单，未达账项正确                  |
| **P3-3 报销**       | 飞书报销表单字段映射、实例解析入库、发票影像归档、借款核销、报销→付款                                                 | 明细合计与合计金额不一致阻断；发票号防重      | 飞书提交一单 → 5 分钟内系统出报销单 → 付款 → 生成凭证 |
| **P3-4 工资入账**   | 接收 P2 月度汇总，生成计提/发放/缴纳凭证                                                                              | 按部门辅助核算；重复推送幂等                  | 工资凭证与工资表勾稽一致                              |
| **P3-5 打通与结账** | 报销→付款→凭证全链路；期末结账；三类报表出数                                                                          | 结账前交叉校验（差异 >2% 阻断）               | 完整走完一个月并结账                                  |

## 七、二期与明确不做

**二期**：税务全部（增值税/附加/企税/个税/印花/出口退税/收汇核销/代扣代缴/申报日历/开票登记）、成本与利润（成本事实/分摊/三层毛利/多维系损益/经营看板）、固定资产、合同台账、预算、真实渠道接入、采购付款与库存、头程成本分摊、内容工厂。

**不做**：银企直连、开票直连、税局申报直连、OCR/发票查验、多账套、合并报表、SaaS 多租户与计费。

## 八、关键路径与里程碑

```
M1  P1-1 完成  → 权限正确，系统可用
M2  P1 完成    → 组织与审批数据自动进来
M3  P2-5 完成  → 能算薪、能出工资条
M4  P3-3 完成  → 报销闭环跑通
M5  P3-5 完成  → 一个月账能结
M6  P4-6 完成  → 业务链路可演示
```

关键依赖：P2-5（算薪）→ P3-4（工资入账）；P3-1（记账）→ P3-3（报销凭证）；P2-1（档案）→ P2-4 / P2-5。

## 九、技术约定与门禁

- 后端：NestJS 模块级 DDD 四层，Controller 不直连 Prisma，统一 `ok()` / `page()`，软删除 + 自增 id + `createdAt/updatedAt`，Swagger 注解齐全。
- 前端：admin-web 用列表页模板（筛选/操作行/表格/抽屉/骨架屏），mobile-web 用卡片列表；样式只走 Tailwind 预设。
- 每个 application service 配单测（成功 + 失败路径）。
- 提交前 `pnpm verify:quick` 全绿；改代码后 `pnpm state:update`；改业务口径同步 `business-snapshot`。
- 每个新模块先有 ADR。
