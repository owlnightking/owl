# 002: 重定产品领域地图与开发排期（组织支撑域先行，主领域与副业域分列）

- 日期：2026-09-07
- 背景：仓库既定主线为「主领域 = 自研产品跨境电商 13 阶段机会流水线 + owl-web 工作台」（原 implementation-plan Phase 2，未启动）。与业务逐题对齐后确认：公司主领域确为自研产品跨境电商，但团队当前要交付的能力是覆盖组织协同 / 激励 / 知识的内网支撑——移动端承担员工的消息 / 审批 / 认可触点，管理台承担运营管理。仓库文档主线与实际开发顺序已脱节，需重排并记录收敛后的需求基线。
- 决策：
  1. **领域三分**：
     - 主领域：自研产品跨境电商业务系统（13 阶段流水线 / 利润聚合 / owl-web 工作台）——远期主体，原规划保留待启
     - 组织支撑域：认可中心、人才中心、智能客服 + 内部知识库、基础配置与监控、协同底座（RBAC / 消息 / 文件 / 配置）——当前开发对象
     - 副业域：付费知识（移动端与 web 端 md 组件创作的文档库，文本入库持久化，商业化后置）——组织支撑域之后启动
  2. **开发排期**：先组织支撑域，再副业域，最后主领域业务主干。
  3. **组织支撑域关键基线**（逐题收敛，细则见 implementation-plan）：
     - 触点按角色而非按端；RBAC 到按钮级、四层统一（菜单可见 / 页面可进 / 按钮可点 / 接口校验），跨 admin / owl / cron / mobile
     - 初期仅内置「超管 / 普通员工」两角色，运营职能先由超管承担
     - 里程碑 1 = 认可中心闭环（仅 admin + mobile 两端落地）
     - 登录：本地用可切换用户 / 角色的 mock 通道验收，生产走真实飞书 OAuth
     - 内站消息先轮询（30~60s），接口预留升级位
     - 知识库（业务文档 / 系统指南 / 组织文档）与 AI 问答配合；付费知识不做商业化、支付与对外入口
  4. **原计划处置**：原 implementation-plan 的 Phase 2（13 阶段流水线）整体平移为主领域远期阶段；Phase 0/1 已完成部分视为历史基线保留。
- 后果：
  - 近期验收对象与里程碑定义更新为支撑域（认可闭环 → 人才 → 客服知识 → 基础配置监控），副业与主领域顺序后置
  - owl-web 近期仅承载角色裁剪下的既有页面可见性，不新接支撑域模块；cron 保留现有任务中心基础（表单同步 / 数据监控探针后续挂载）
  - 需同步 `docs/implementation-plan.md` 与 `docs/PROJECT_STATE.md`；后续新增支撑域模块与数据模型（认可 / 人才 / 知识库 / 文档 / 统计 / 监控等）时同 commit 更新状态文档
  - 风险：需求仍在演进，里程碑内细则（如徽章图片素材、体力 / 币额参数、知识库分类）在对应阶段开工前再确认，以 system-config / field-config 承载可调部分
