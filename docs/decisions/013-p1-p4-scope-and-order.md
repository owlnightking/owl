# 013: P1–P4 实施顺序与范围定稿（取代 002 排期、011 权限口径与旧 MVP 流水线）

- 日期：2026-11-11
- 背景：
  - `002` 定的开发顺序是「组织支撑域 → 副业域 → 主领域」，`011` 定产品线骨架时写「权限沿用全员平权，后续再拆」，`grill-mvp-decisions.md` 定的是「13 阶段单对象流水线」。
  - 业务重新对齐后确认：当前阶段的目标是先把**自用系统**跑通，SaaS 后置；系统按「基座 → 人才 → 财务 → 业务」四期建设，人才与财务是必须补齐的组织能力，不再冻结。
  - 旧文档的排期、冻结清单与权限口径若继续保留，会直接误导后续开发（例如把人才中心列为「不做」、把利润引擎排在人才/财务之前）。
- 决策：
  1. **实施顺序固定为 P1 → P2 → P3 → P4**：
     - P1 系统基座：权限码表单源与四层校验、角色授权、飞书组织同步、登录兜底、飞书审批记录、编号/导出/字典/审计。
     - P2 人才中心：招聘面试、员工档案、异动、免打卡月度考勤（上级系统内确认后锁定）、薪酬（含社保公积金与个税）、绩效三档、奖惩、员工自助。
     - P3 财务一期：记账内核、资金出纳、报销与费用（飞书填单解析）、工资/社保/个税入账。
     - P4 业务链路：立项 → 研发设计 → 手办样 → 供应链（供应商/报价/试单）→ 营销 → TikTok Shop 模拟数据，跑通即可。
  2. **范围边界**：财务一期只做记账/报销/出纳；税务、成本与利润、固定资产、合同台账、预算、真实渠道接入、采购付款与库存、内容工厂均为二期。SaaS 多租户与计费不做。
  3. **权限口径**：`011` 的「全员平权、后续再拆」**即刻失效**，统一按 `012` 的权限注册表 + 四层校验执行；新增模块必须先登记权限点。
  4. **旧文档处置**：
     - 本 ADR 取代 `002` 的「开发排期」结论；
     - 本 ADR 取代 `011` 的权限口径（第 5 条）；
     - `grill-mvp-decisions.md` 的 13 阶段流水线仅作历史输入，不再作为实施目标；
     - `docs/business/*` 旧战略文档已由用户移除，不再作为业务或排期依据；其残留的「冻结人才中心 / 利润引擎先行」口径一并失效。
  5. **文档权威**：`docs/implementation-plan.md` 是唯一的排期与范围事实源；`docs/business-snapshot.md` 是业务功能现状；ADR 只记录历史决策，冲突时以编号更大的 ADR 为准。
- 后果：
  - 正向：所有文档对「先做什么、不做什么」只有一个答案；人才中心与财务中心不再被误判为冻结。
  - 负向：`002` / `011` 的原文仍保留（ADR 只追加不修改），读者需通过本 ADR 了解其被取代的部分。
  - 约束：后续若调整四期顺序或范围，必须新开更高编号 ADR，并同步 `implementation-plan.md` 与 `business-snapshot.md`。
